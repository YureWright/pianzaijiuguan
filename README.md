# 骗子酒馆 MVP

## 体验优化分支

本分支提供可本地运行的体验优化版，历史公网地址尚未更新为此版本。

- 写实酒馆环境、胡桃木桌沿、织物桌布、纸张与金属质感；美术资源全部在本地提供。
- 桌面牌桌与操作区同屏，手机手牌区固定在底部；座位名称与牌背分开排布。
- 选牌保留卡片节点与焦点，支持提前选牌、理牌、清空选择，以及 `1–5`、`Enter`、`Esc` 快捷键。
- 出牌、亮牌与轮盘节奏更紧凑，提供完整 / 简化动效与语音偏好；保留 AI 喊话和字幕。
- 暂时断网时保留牌桌，恢复连接后回到原座位；淘汰后刷新可以继续观战。
- 修复匿名观战读取手牌和旧入桌接口绕过登录的问题。

素材来源与完整生成提示词见 [美术资源说明](docs/ART-DIRECTION.md)。验收命令：

```bash

npx playwright install chromium
npm test
npm run test:play
```

浏览器验收使用真实本地服务和真实界面按钮，不替换游戏接口、不加速游戏时钟。覆盖双账号、桌面与手机视口、完整牌局与重开、改名、排行榜、聊天、掉线重连和 WebRTC。截图、录像及 JSON 结果输出到 `test-results/acceptance/`。WebRTC 使用 Chromium 测试摄像头；跨公网 TURN 与真实手机硬件需在部署环境验收。

一个可本地运行、也可公网部署的 Liar's Bar 风格网页游戏。固定上海/杭州双城账户、唯一常驻主桌、AI 自动补位、摄像头 P2P 视频、多模型 AI 角色，以及跨局用户与 AI 排行榜。

## 已实现

- 唯一主桌：不创建房间，不输入房间码；登录后直接进入同一张牌桌。
- 固定双城账户：上海、杭州各一个账户，使用各自密钥登录；最多两位真人，其余席位由 AI 补齐。
- 用户名规则：用户名自动标注地点前缀，两个账户不能重名；被淘汰后必须更换用户名才能参加下一局。
- 20 张特制牌：J、Q、K 各 6 张，加大小王两张万能牌；四人各 5 张。
- 原版核心循环：桌面公开 J/Q/K、每回合扣 1 到 3 张牌、质疑亮牌、俄罗斯轮盘、最后存活者获胜。
- 大小王为万能牌，挑战亮牌时永远算作桌面点数。
- 连续牌局：枪响或质疑后不重新发牌，手牌保留；全员空手时只能质疑。
- 真人全灭后，所有存活 AI 会自动明牌，方便观战复盘。
- 实时联机：同一主桌通过 SSE 同步状态，刷新页面可恢复本人座位与手牌。
- 大尺寸摄像头区域：浏览器原生 WebRTC 点对点传输，不录制、不落盘。
- 管理员后台：统一配置 AI 角色、供应商、模型、API Key、头像和启用状态。
- 每位 AI 都有完整人物立绘；管理员可以为每个角色上传独立立绘替换默认素材。
- 每局阵容选择：玩家只能从管理员已启用的 AI 角色中选择。
- AI 记忆与战术：记录历史质疑、亮牌结果和对手倾向，跨轮次更新判断。
- AI 公开喊话：AI 回合会先观察牌桌，再通过 SSE 逐字流式展示挑衅式公开喊话，最后显示最终抉择并执行动作。
- 发言分层：回合中只公开面向所有人的挑衅/拉拢式喊话；真实私人想法在牌局结束后通过“赛后心声”展示。
- 行动节奏：真人每次 30 秒出牌时间；AI 本地思考停顿约 1.2–2.4 秒，远端模型响应另计。AI 喊话使用浏览器语音结束回执；浏览器语音未启动或异常挂起时自动释放等待。
- 动画反馈：出牌飞行约 0.95 秒，质疑提示约 0.65 秒，翻牌判定约 1.8 秒，独立轮盘约 3.8 秒。关键播报与画面同步，简化动效模式进一步减少动态效果。
- 胜利结算：牌局结束后先播放独立胜者结算画面，展示胜者与最终席位排名；结算关闭后才对死亡玩家弹出强制改名。
- 处决构图：亮牌阶段展示质疑者、被质疑者、实际牌面与判定结果；处决阶段败者立绘与完整左轮同框，包含转轮、击锤、枪口闪光、弹孔、震屏和音效。
- 舞台特效：灯光扫过、粒子爆发、判定震屏、高光 REC 标记和电影黑边，关键节点会自动放慢节奏。
- 全程语音：浏览器内置 SpeechSynthesis 播报回合、出牌、质疑、判罚、胜负和复盘；不同角色与情绪使用不同语速和音高。
- 背景音乐：管理员可配置音频 URL、上传音频文件、设置音量并启停；游戏内提供播放/静音按钮，语音播放时自动降低音乐音量。
- 座位气泡：AI 的观察、放话和抉择显示在对应座位头像旁；牌桌中央只展示桌面牌、扣牌和亮牌。
- 动画层级：打牌、质疑亮牌和回合变化都在牌桌内完成，只有处决与最终胜利结算使用全屏覆盖。
- 语音与节奏：AI 喊话拥有更高优先级；关键判定播报与画面同步，处决与结算在相应演出完成后推进。可以选择仅角色语音或关闭语音。
- 操作音效：翻牌、亮牌、出牌、转轮、空枪、中弹和胜负都有独立音效，可与语音同时播放。
- 无模型 Key 时自动使用本地策略，不会卡住对局。
- 断线 9 秒后 AI 托管；房主掉线时可转移房主。
- 排行榜：用户按成功欺骗、成功击杀（成功质疑 / 被质疑反杀）、最多连续获胜排名；AI 按胜率排名。

## 管理员后台

访问 `/admin.html`，例如线上地址：

```text
https://115.29.243.90:8443/admin.html
```

首次启动时使用 `.env` 中的 `ADMIN_PASSWORD` 创建管理员密码。密码只在第一次生成配置文件时使用，之后请在后台“修改密码”中更新。

后台可以：

- 新增、编辑、删除 AI 角色。
- 设置角色名称、头像 Emoji、上传头像图片。
- 设置角色完整立绘、AI 提示词和表情头像。
- 每个角色可单独上传头像和 3:4 人物立绘。
- 配置 OpenAI-compatible、Anthropic 或 Gemini 接口、模型名和 API Key。
- 启用或停用角色。玩家端只能选择已启用角色。
- “危险操作”区可重置排行榜：清空两个账户的用户名、用户战绩和 AI 统计，登录密钥保持不变；对局进行中禁止重置。

默认预置 DeepSeek、GPT、Claude、Kimi、豆包、千问六个角色，密钥需要管理员自行填写。
默认立绘位于 `public/portraits/`，管理员上传的立绘会覆盖默认素材。

支持的接口格式：

- `OpenAI 兼容`：`POST {baseUrl}/chat/completions`，适合 OpenAI、OpenRouter、DeepSeek、通义、Moonshot、Ollama 等兼容接口。
- `Anthropic`：`POST {baseUrl}/messages`。
- `Gemini`：`POST {baseUrl}/models/{model}:generateContent`。

例如本地 Ollama：

```text
供应商：OpenAI 兼容
URL：http://127.0.0.1:11434/v1
模型：llama3.1
Key：留空
```

注意事项：

- API Key 保存在服务端 `data/config.json`，文件权限为 `0600`，不会通过 SSE 或公开 API 返回。
- 后台只显示 Key 的掩码，不会回显完整内容。
- 修改 Key 时留空表示保留原 Key，勾选“清除已保存的 API Key”才会删除。
- 没有 Key 或接口调用失败时，该 AI 自动回退到本地策略。

## 游戏规则

1. 每轮公开一个 J/Q/K 桌面点数，所有出牌都宣称属于该点数。
2. 当前玩家选择 1 到 3 张手牌扣下，可以如实出牌，也可以撒谎。
3. 下一位玩家可以质疑上一位出牌，或继续出牌；质疑不会重新发牌。
4. 质疑后只亮出上一位玩家最后打出的牌：若撒谎，出牌者扣扳机；若属实，质疑者扣扳机。大小王算万能牌。
5. 每把左轮 3 个弹仓、1 发子弹，每次扣扳机约有 1/3 概率中弹。中弹即出局，空枪继续。
6. 手牌打空不等于淘汰。存活人数大于 2 时，空手玩家自动跳过，由下一位仍有手牌的人行动。
7. 只剩 2 人时，空手玩家面对上一位的出牌必须质疑；若上一位刚完成质疑，则自动跳过。全场只剩最后一名持牌者且上一手来自其他玩家时，他不能出牌，必须质疑。
8. 只有手牌耗尽、只剩一名持牌者，或只剩一名玩家存活时牌局才结束；终局质疑由胜者赢下牌局。

当前 MVP 聚焦核心牌局，不包含原版中的角色技能、道具、复杂动画和场景交互。

## 联机与摄像头

- 状态同步使用 SSE，服务端维护唯一主桌的内存状态，不依赖数据库。
- 账户、用户名和排行榜数据持久化到 `data/accounts.json`，权限为 `0600`。
- 每个真人席位有独立玩家令牌；操作、聊天、SSE 订阅和 WebRTC 信令都校验令牌，公开状态不暴露手牌或令牌。
- 真人视频使用 WebRTC P2P；默认只配置公共 STUN。
- 同一台电脑或局域网通常可以直接连接；跨公网 NAT 建议配置 TURN 中继。
- 摄像头需要 HTTPS 或 localhost 才能使用。
- 视频只发送给主桌上的另一位真人，不经过业务服务器，不录制。
- 语音播报完全在浏览器本地合成，不经过服务器，也不需要额外 TTS Key。

## 配置

复制 `.env.example` 为 `.env` 后可修改：

```powershell
Copy-Item .env.example .env
```

常用变量：

- `PORT`：服务端口，默认 `3000`。
- `HOST`：监听地址，默认 `127.0.0.1`。公网部署时改为 `0.0.0.0`。
- `ADMIN_PASSWORD`：首次生成 `data/config.json` 时使用的管理员密码。
- `SHANGHAI_LOGIN_KEY` / `HANGZHOU_LOGIN_KEY`：首次生成账户文件时使用的上海/杭州登录密钥。
- `DATA_DIR`：管理员配置和 AI 角色数据目录，默认 `./data`。
- `ICE_SERVERS`：WebRTC ICE 配置 JSON。跨公网联机请加入 TURN。

TURN 示例：

```text
ICE_SERVERS=[{"urls":"stun:stun.l.google.com:19302"},{"urls":"turn:turn.example.com:3478","username":"user","credential":"pass"}]
```

## 后续部署提醒

当前版本已完成固定账户鉴权和本地持久化。正式公网运营前至少还需要：

- 为登录、操作和排行榜接口增加限流、审计和反作弊。
- 使用 HTTPS 反向代理访问页面。
- 配置 TURN 服务，并让 `ICE_SERVERS` 指向该服务。
- 将模型 Key 放到服务端密钥管理，而不是浏览器输入。
- 增加日志脱敏、会话监控和异常告警。
